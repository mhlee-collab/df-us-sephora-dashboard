# DF_US 세포라 대시보드

Dr.FORHAIR 미국(세포라) 전용 대시보드. **통합 탭 · 유입 채널 탭** 2개.

```
GitHub Pages  ──  index.html (단일 파일)
                        │ fetch  /exec?token=…
                        ▼
        Google Apps Script 웹앱  ──  Drive JSON 캐시 (30분 트리거)
                        │ 파싱
                        ▼
          구글 시트 [DF_US] 세포라 대시보드 RAW
             구분자 · RAW_commerce · RAW_유입
```

| | |
|---|---|
| Pages | https://mhlee-collab.github.io/df-us-sephora-dashboard/ |
| 접근 | Google OAuth · `@wyattcorp.com` 계정 전용 |
| Apps Script | `DF_US 대시보드 API` (RAW 시트 컨테이너 바인딩) |
| 배포 설정 | **실행: 나(MJ) / 액세스: 모든 사용자** — 아래 「접근 게이트」 참고 |
| 환율 | $1 = 1,500원 |

## 접근 게이트

🛑 **액세스는 「모든 사용자」로 둔다. 「도메인 내 사용자」로 두면 대시보드가 아예 안 뜬다.**

「도메인 내 사용자」면 `/a/macros/wyattcorp.com/s/<ID>/exec` 주소가 발급되는데,
이 주소는 구글 로그인 페이지로 302 를 쏘면서 `Access-Control-Allow-Origin` 을 주지 않는다.
브라우저 주소창으로 직접 열면 쿠키가 실려 정상 응답이 오지만,
cross-origin `fetch` 는 기본값이 `credentials:'same-origin'` 이라 쿠키가 안 실려
**`Failed to fetch`** 로 떨어진다. (2026-08-14 실측 · 운영 중인 UNOVE 배포도 「모든 사용자」다.)

**「모든 사용자」라도 데이터는 열리지 않는다.** 진짜 게이트는 `Code.gs` 의 `verifyToken_()` 이고,
아래 4개를 **전부** 만족해야 통과한다.

| # | 검사 | 실패 시 |
|---|---|---|
| 1 | 구글이 유효하다고 답하는 액세스 토큰인가 | `INVALID_TOKEN` |
| 2 | **이 대시보드의 클라이언트 ID로 발급된 토큰인가** (`audience`) | `WRONG_AUDIENCE` |
| 3 | 확인된(verified) 이메일인가 | `UNVERIFIED_EMAIL` |
| 4 | `@wyattcorp.com` 계정인가 | `UNAUTHORIZED_DOMAIN` |

🛑 **2번을 빼지 말 것.** 없으면 도메인 검증이 사실상 무력해진다 — 와이어트 직원이
구글 로그인으로 접속한 아무 제3자 사이트가 그 직원의 액세스 토큰을 갖게 되고,
그 토큰을 이 엔드포인트에 넣으면 `tokeninfo` 는 여전히 `@wyattcorp.com` 을 돌려준다.
액세스가 「도메인 내 사용자」였을 때는 구글 세션이 이 구멍을 가려주고 있었다.

⚠️ **실행 계정은 반드시 「나(MJ)」** — 웹앱이 MJ 권한으로 시트를 읽으므로
팀원에게 시트를 개별 공유할 필요가 없다.

프런트는 반드시 **일반형** `/macros/s/<ID>/exec` 를 부른다. 배포 ID 는 두 형태가 동일하다.

## 처음 세팅 (Apps Script)

1. `apps-script/Code.gs` 전체를 스크립트 편집기에 붙여넣고 저장
2. **시트 ID** — 컨테이너 바인딩이라 보통 그대로 돈다.
   시트를 갈아끼울 때만 `프로젝트 설정 → 스크립트 속성` 에 `SPREADSHEET_ID` 추가
   (🛑 리포지토리가 공개라 코드에 시트 ID를 박지 않는다)
3. 함수 드롭다운에서 **`checkSheet`** 실행 → 로그에 탭 3개가 `✔` 로 뜨는지 확인
4. **`setupCacheTrigger`** 실행 (최초 1회)
   · Drive 권한 승인 요청이 뜨면 승인
   · 로그에 **「캐시 갱신 완료: N bytes, N초」** 가 떠야 진짜 성공이다.
     「실행이 완료됨」만 뜬 건 성공이 아니다
5. **`checkTotals`** 실행 → 합계가 `test/README.md` 의 기대값과 맞는지 대조
6. 배포 → **배포 관리 → 연필 → 버전: 새 버전 → 액세스: 모든 사용자 → 배포**
   (실행: 나 는 그대로 둔다. `/exec` 배포 ID 는 바뀌지 않고 주소 형태만
   `/a/macros/wyattcorp.com/s/…` → `/macros/s/…` 로 바뀐다)
7. CORS 가 열렸는지 확인 — 아래가 `Access-Control-Allow-Origin: *` 를 뱉어야 한다

```bash
curl -s -o /dev/null -D - -H "Origin: https://mhlee-collab.github.io" \
  "https://script.google.com/macros/s/<배포ID>/exec?token=DUMMY" \
  | grep -i "^HTTP/\|^access-control-allow-origin:"
```

## 재배포

🛑 **「배포 관리 → 연필 → 새 버전」만 쓴다.**
「새 배포」를 누르면 `/exec` 주소가 새로 발급돼 대시보드가 구버전을 계속 바라본다.
OAuth `redirect_uri` 와 Pages 호스트도 하드코딩돼 있으니 **리포지토리 이름·계정명·Pages 주소를 바꾸지 않는다.**

★ Apps Script 는 **재배포 없이도 프로덕션에 반영된다** — 30분 트리거가 저장된 최신 코드로 캐시를 굽기 때문.
단 `?only=` · `doPost` 처럼 **캐시를 안 거치는 경로는 배포된 버전의 코드로 돈다** → 그쪽을 고쳤으면 반드시 새 버전 배포.

## 엔드포인트

| 경로 | 동작 |
|---|---|
| `/exec?token=` | 현재 캐시 반환 (라이브 파싱 아님) |
| `?fresh=1` | 캐시 우회 + 라이브 파싱 + 캐시 재작성 — 사이드바 `↻ RAW` 버튼이 이걸 붙인다 |
| `?only=meta\|commerce\|channel` | 단일 섹션 경량 경로 (캐시 미경유) |

응답에 `updatedAt` · `cacheBuiltAt` · `servedFrom` 이 실려 있다. 화면 우상단에서 `servedFrom` 을 볼 수 있다.

## 시트 규칙

🛑 **열 추가는 언제나 맨 오른쪽.** 중간 삽입은 파서를 깨뜨린다.
파서는 **완전 일치 헤더명**으로만 열을 찾고, **열 개수·필수 헤더를 검증**한다.
열이 줄거나 헤더명이 바뀌면 실제 헤더 목록을 실은 에러로 즉시 멈춘다.
탭 이름 · 헤더명을 바꾸지 않는다. 값 갱신은 안전.

| 탭 | 기준 열 수 | 대시보드 키 |
|---|---|---|
| `구분자` | 9 | SKU 매핑 정본 — 조인 키는 **언제나 `Sku Number`** |
| `RAW_commerce` | 24 | 통합 탭 — 방문 · 매출 · 주문 · 전환 |
| `RAW_유입` | 17 | 유입 채널 탭 (M열은 헤더 없는 상수 1500) |

## 화면 구성 (2026-08-16 기준)

**공통** — 기본값은 **일(day) 보기 · KRW(백만원)**. 통화는 **대시보드 공용**이라 두 탭의 칩이 같은 값을 가리킨다.
환율 `$1 = 1,500원` 은 코드 상수다. 🛑 시트에 수식으로 두지 않는다.

| 통합 대시보드 | 유입 채널별 |
|---|---|
| KPI 4장 (누계 + 최근 기간 비교줄) | KPI 4장 (기준 기간 + NA 매출) |
| MONTH · WEEK 필터 | MONTH · WEEK 필터 (채널 필터 없음) |
| 통합 성과 그래프 (월/주/일 · 통화 칩) | Overview — 전 채널 합산 고정 |
| └ 데이터 테이블 (기준 열 sticky) | 유입 채널 랭킹 (VISITS·SALES·CVR × best3/worst3) |
| | Visits · Sales by Channel — 차트 2개 + 표 |
| | Conversion TY (%) by Channel — 차트 + 표 |

🛑 **화면에 설명 주석을 달지 않는다.** 매출 원천·CVR 정의·단위 기준은 이 문서와 코드 주석에 남기고
화면에는 올리지 않는다 (MJ 결정 2026-08-16). 단위는 **지표명·축 제목이 진다** — 셀에는 붙이지 않는다.
예외는 「데이터가 실제로 깨진 경우」의 시트 경고뿐이다.

**KPI 비교줄** — 월/주/일 토글을 따라 `DoD` · `WoW` · `MoM` 이 자동으로 바뀐다.
큰 숫자는 「필터 범위 누계」, 비교줄은 「최근 기간 vs 직전 기간」이라 **서로 다른 구간**을 말한다.
그래서 비교줄에는 기간 라벨을 반드시 함께 적는다. 라벨·수치는 전부 데이터 파생이라 시트만 갱신하면 따라온다.
🛑 `setMainPeriod` 는 `renderKPI()` 를 반드시 함께 부른다 — 빼면 일·월로 바꿔도 「WoW」가 남는다.

**단위 표기** — 통합 탭 데이터 테이블은 KRW·USD 모두 **정수**(주 단위라 1·15·13 처럼 읽힌다).
유입 채널 탭 셀은 **소수점까지 살린다** — 채널 하나의 매출은 $92(=0.14백만원) 수준이라
정수로 자르면 대부분 0 이 되고 랭킹 1위마저 3 으로 뭉갠다.

## 데이터 규칙 — 어기면 수치가 틀린다

**🛑 `NA` 채널** (방문 0 · 매출만 있는 미귀속 매출)

| 용도 | 처리 |
|---|---|
| 채널 차트 · 채널별 표 · 랭킹 | 제외 |
| 매출 합계 · KPI | **포함** — 빼면 통합 탭과 13.6% 어긋난다 |
| 전환율 | 분모 0이라 `-`. 0으로 찍지 않는다 |
| 경고 | **화면에 표시하지 않는다** (2026-08-16 변경) — 아래 참고 |

🛑 **NA 비중 경고 배너는 화면에서 제거했다** (MJ 결정 2026-08-16).
경영진·BM팀이 매번 읽어야 할 정보가 아니고 데이터가 부실하다는 오해를 준다.
**계산 규칙은 그대로 유지**하고, 감시는 Cowork 의 raw 확인 · 누적관리 단계와
Apps Script `checkTotals` 로그가 맡는다.

**⚠️ 방문 정의 차이** — `RAW_유입` 방문 < `RAW_commerce` 방문. 집계 단위가 다르다.
**방문당 매출 · 전환율은 반드시 같은 탭 안에서** 계산한다. 교차 계산 금지.

**⚠️ 그 밖**

- 값 0인 채널은 원본에서 행 자체가 빠진다 → 파서가 0으로 채워 계열이 끊기지 않게 한다.
  🛑 이 채움 사실을 **화면에 띄우지 않는다** — 내부 처리 규칙이다. `Code.gs` 는 `warnings` 가 아니라
  `diagnostics` 로 내보내고, `warnings` 는 「데이터가 실제로 깨진 경우」에만 쓴다
- `LY` · `YoY` 열은 전 기간 0(미국 첫 해) → 화면에서 제외
- **7/29 · 7/30 은 매출 0 · 방문 정상.** 세포라 입점일이라 정상값이다.
  결측 처리하지 않는다. 「매출 0 = 셧다운」 보정 로직을 넣지 말 것
- 전환율은 원본 `Conversion TY` 를 그대로 쓴다. 재계산하지 않는다
  (통합 탭 CVR = 주문 수량 ÷ Visits TY 는 이 값을 방문 가중 합산한 것과 **정확히 같다**)
- `년` · `월` 은 **일자 기준**으로 자른다. 주 기준으로 자르면 월 합계가 어긋난다
- `Sales 파싱` · `매출(현지 통화)` 는 UNOVE 잔재다. 파서는 참조하지 않는다
- **화면 문구에 주차 수·개수를 새로 박지 않는다.** 회차 라벨은 전부 `D.weeks` 파생

⚠️ **성능 수치는 인용 전에 반드시 재측정.**

## 채널 멀티선택 표시 방식 (Dr.FORHAIR 설계 → UNOVE 역이식 예정)

UNOVE 미결 항목이었다. 지표 3개 × 채널 N개를 **한 화면 3축에** 얹으면 축이 서로를 눌러 아무것도 안 읽힌다.
Dr.FORHAIR 결론(2026-08-16): **모드를 갈아끼우지 말고, 지표마다 차트를 따로 둔다.**

| 영역 | 동작 | 채널 선택 |
|---|---|---|
| **Overview** | Sales(막대) + Visits(면) + CVR(선) 3축 오버레이 — **언제나 전 채널 합산 · 형태 고정** | 없음 |
| **Visits · Sales by Channel** | VISITS TY · SALES TY 차트를 좌우로 + 그 아래 지표별 행 블록 표 | 이 블록 전용 드롭다운 |
| **Conversion TY (%) by Channel** | CVR 차트 + 그 아래 표 | 이 블록 전용 드롭다운 (위와 **독립**) |

- 상단에 채널 필터를 두지 않는다. 하나만 두면 모든 영역이 같이 움직여 비교가 안 된다.
- CVR 을 따로 뗀 이유 — 분모(방문)가 작은 채널이 100% 로 치솟아 Visits·Sales 화면을 눌러버린다.
- 기본은 **NA 를 뺀 전 채널 표시**. 드롭다운은 골라 보라고 둔 도구이지 기본을 좁히라는 뜻이 아니다.
- 표 정렬은 **가장 최근 기간 값 기준 내림차순**이며 지표 블록마다 자기 지표를 기준으로 삼는다.

검증 후 UNOVE 로 역이식한다. **UNOVE 리포지토리 · Apps Script · 시트에는 손대지 않는다** (읽기만 가능).

한때 막대를 채도 낮춘 단(`#C2183A`), 토글을 옅은 레드로 갈라 봤으나 붉은색이 여러 단으로 보여 혼잡했다.
대신 **큰 면적은 차콜이 받는다** — 사이드바 전체(200px × 화면 높이)를 레드로 칠하면 눈이 아프다.
소개서에서도 레드는 로고·헤드라인 같은 포인트에 쓰이지 대면적 배경으로 쓰이지 않는다.

| 역할 | HEX |
|---|---|
| **사이드바 배경** | `#22222A` — 차콜. 🛑 레드 아님 |
| 메인 레드 (CI) | `#DD061A` — 매출 막대 · 컨트롤 active · 사이드바 active 메뉴 · 로고 마크 |
| 레드 (짙음) | `#D41112` — 소개서 값이나 **화면에서는 쓰지 않는다** (레드 단일 원칙) |
| 서브 블루 | `#156FB8` — 방문 |
| 서브 블루 (보조) | `#0070C0` — 주문 수량 |
| 서서브 퍼플 | `#6C237C` — CVR |
| 세포라 레드 | `#c8102e` — 상단 헤더 하단 3px 보더 (세포라 공통이라 브랜드 무관 · 유지) |
| 상태색 | 상승 `#16a34a` / 하락 `#dc2626` — 브랜드 레드와 별개 축 |

색은 **CSS 토큰**(`--sidebar` · `--bar` · `--tgl-on-bg/bd/fg`)으로만 정의하고 사용처는 토큰만 본다.
다시 다듬을 때 토큰 값만 바꾸면 되고, `node test/run.js` 가 「붉은 계열이 한 종류인지」를 지킨다.

유입 채널 14종은 **UNOVE 세포라 대시보드와 완전히 동일한 고정색**을 쓴다 — 두 대시보드를 나란히 보는
사람이 같은 채널을 같은 색으로 인식해야 하기 때문이다.
⚠️ 알고 받아들인 트레이드오프 — `Push #E06666` 과 `Brand Media #CC0000` 은 색각 시뮬레이션에서
분리도가 기준 미달이고, 14계열을 한 화면에 켜면 하위 채널끼리도 겹쳐 보인다. **색을 바꾸는 대신
계열 수를 사용자가 고를 수 있게** 각 블록에 드롭다운을 뒀다.
